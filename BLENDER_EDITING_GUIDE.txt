SCHEDULE I ARCADE - BLENDER EDITING (M2.38)

Blender is now a supported layout editor for the raw runtime scene.

FIRST TIME
1. Double-click OPEN_ARCADE_IN_BLENDER.cmd.
2. The script imports UnityAssetsToCopy/Assets/ScheduleIArcade/Source/arcade.fbx.
3. It relinks the supplied textures, hides the placeholder crane/vending meshes, creates clean pivots,
   applies the corrected M2.37 starting layout, and saves:
      BlenderEditable/ScheduleIArcade_Editable.blend

EDITING
- Move/rotate Pinball Machine, Arcade Machine, Table Top (Pac-Man), Air Hockey, etc. normally.
- RED_DOOR_GUIDE / ARCADE_DOOR_TARGET = generated double-door position on the chamfer.
  Slide ARCADE_DOOR_TARGET ALONG the diagonal wall if you want to fine tune the door location.
- GREEN_PINBALL_GUIDE = pinball row.
- ORANGE_ARCADE_CABINET_GUIDE = upright cabinet area.
- BLUE_PACMAN_GUIDE = Pac-Man area.
- Keep machines upright. Z rotation is supported directly by the runtime exporter.
- Crane Game and Vendind Machine stay hidden, but remain in the .blend because the runtime package expects all 7 source meshes.

USING YOUR EDITS IN GAME
1. SAVE the .blend in Blender (Ctrl+S).
2. Close Blender or leave it open.
3. Run BUILD_AND_INSTALL.cmd.
4. Build-And-Install automatically detects BlenderEditable/ScheduleIArcade_Editable.blend and Blender.exe.
5. Blender runs headless for a moment and rewrites the runtime mesh package as version 2.
6. Launch Schedule I. The log should say:
      Loaded Blender-authored arcade prop transforms from raw scene package v2.

You do NOT need Unity for ordinary machine placement anymore.
The room footprint and generated chamfer door are still handled safely by the mod so collision/entry behavior remains intact.

M2.38 note:
- stale FBX animation tracks are stripped during first-time preparation, so machine placement,
  rotation, and scale now remain stable after saving and reopening the .blend.
- the sealed ceiling, baseboards, red/white crown neon, ceiling panels, polished floor, door hardware, and runtime lighting
  are generated by the mod; the Blender file continues to focus on machine layout.
- every build exports the actual visible-machine bounds and stops with a clear layout-QA error if
  a machine crosses the room shell, overlaps another machine, or pulls a wall row out of alignment.
