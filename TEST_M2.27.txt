Schedule I Arcade M2.27 - disappearing placed furniture fix

WHAT THE LOG REVEALED
M2.26 stopped the placement NullReferenceException, but the placed TV could still vanish.
Two native lifecycle details were still wrong:
1. The cloned Grid inherited the source Grid's serialized GUID and Awake registered it before
   M2.26 called RegenerateGUID. RegenerateGUID only changes the serialized GUID string; it does
   not update the live Grid.GUID/GUIDManager entry after Awake.
2. Vanilla GridItem networking can parent the spawned object under OwnerGrid.Container, which is
   the source owned property's content container rather than the custom arcade room.

M2.27 FIX
- Builds the proxy Grid under an INACTIVE staging parent.
- Regenerates the proxy GUID before Grid.Awake is allowed to run.
- Activates the proxy only after the Property hierarchy, Tile.OwnerGrid references, colliders and
  world transform are ready.
- Rejects the proxy if its runtime GUID still matches the source Grid.
- Adds a targeted Harmony postfix for BuildManager.CreateGridItem.
- Furniture created on the arcade proxy Grid is tracked and kept parented to the arcade room after
  FishNet/vanilla spawn initialization so it does not disappear with the template property's
  content container.
- Wall Surface proxies are also prepared while inactive with a valid BakedGUID before Surface.Awake,
  eliminating the M2.26 invalid-GUID FormatException spam.

TEST
1. Run BUILD_AND_INSTALL.cmd.
2. Enter the arcade.
3. Confirm the log contains:
   Arcade floor building enabled ... proxyGUID=...
   Installed arcade GridItem placement retention hook.
4. Spawn/equip a TV.
5. Place the TV on the checkerboard floor.
6. Confirm the log contains:
   Arcade build: captured placed GridItem ... keeping its visual object inside the arcade room ...
7. Wait at least 10 seconds. The TV should remain visible exactly where it was placed.
8. Exit and re-enter the arcade. The TV should still be visible during the same play session.
